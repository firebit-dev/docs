NavigationController

This item only works when running on the client. Client

Draws the "go here" guidance beam: a single Assets.Particles.GuidanceBeam stretched between the local character and a waypoint, which clears itself once the player arrives.

Only one beam exists at a time. NavigationController.startBeam cleans the module maid before building anything, so calling it again retargets rather than stacking beams.

Signals

  • ReachedDestination — fired once the beam's two attachments come within destinationRange studs. Fires immediately, before any connection is made, if the player is already in range at start.
  • BeamCleared — fired from the maid's own cleanup, so it covers every teardown path: arrival, an explicit NavigationController.stopBeam, or a retarget.

isNavigating tracks whether a beam is live. Note that arrival flips it false but leaves the beam drawn — the caller decides whether to also call NavigationController.stopBeam.

Where the beam points

Beam origin. Defaults to the character's PrimaryPart

Arrival radius in studs. Defaults to 4; pass 0 to disable arrival detection entirely

) → Beam?

Draws a guidance beam from source to target, replacing any beam already up. Returns the beam, or nil if either endpoint could not be resolved.

Both endpoints are normalized to Attachments. A BasePart source gets a throwaway attachment parented to it; a Vector3 or CFrame target gets one parented to Workspace.Terrain. Everything created along the way is owned by the module maid, so NavigationController.stopBeam removes it all.

	NavigationController.stopBeam()
end)

stopBeam​

</>
NavigationController.stopBeam() → ()

Clears the active beam and everything created for it — the cloned beam, both throwaway attachments, and the arrival watcher. Clears isNavigating and fires BeamCleared. Safe to call with no beam up.
