Zombie

This item only works when running on the server. Server

Zombie NPC class. Wraps an NPC instance with health, AI state machine, and damage handling.

Each zombie owns a finite state machine whose states live in ServerScriptService.Class.NPC.States (Idle, Roam, Chase, Attack, Death, Seek, Flee). Every state module implements the same Start/Step/Stop contract; SetState stops the outgoing state and starts the incoming one, while Step ticks the active state each frame. A zombie config may set behaviorOverride to the name of a sibling module in the same States folder, which is lazily required and takes precedence over the built-in state for both Start and Step.

Broken require

This module requires ReplicatedStorage.Shared.Types.ZombieTypes, which does not exist in the source tree. Every ZombieTypes.* annotation below therefore fails to resolve and the module cannot be loaded at runtime until that type module is authored. This is a known, pre-existing gap.

new​

model: Model,--

config: ZombieTypes.ZombieConfig--

health, animations and behaviour tuning

) → Zombie

Wraps a rig model in a Zombie, registering any per-state animations declared on the config with the underlying Freshynoid.

The zombie starts in the Idle state with full health, and mirrors its health onto the model as the Health and MaxHealth attributes so other systems can read it without holding a reference to this object.

SetState​

</>
Zombie:SetState(
stateName: ZombieTypes.ZombieStateName--

state to enter

) → ()

Transitions the zombie into a new AI state.

Stops the outgoing state module, records it as previousState, then starts the incoming one. No-ops when already in the requested state, and refuses every transition except Death once the zombie is dead. When the config declares a behaviorOverride, that module is started instead of the built-in state module for the new state.

Step​

</>
Zombie:Step(
dt: number--

seconds elapsed since the previous step

) → ()

Advances the active state by one tick. Called by the owning zombie manager every frame (or less often for distant zombies, per lodTier).

Dead zombies are skipped entirely. A configured behaviorOverride that implements Step replaces the built-in state's step for this tick.

TakeDamage​

</>
Zombie:TakeDamage(
amount: number--

damage to apply

) → ()

Subtracts damage from the zombie's health, clamped at zero, and republishes the new value to the model's Health attribute. Calls Zombie:Die once health reaches zero. No-ops on an already dead zombie.

Die​

</>
Zombie:Die() → ()

Marks the zombie dead, transitions it into the Death state (which plays the death animation and ragdolls the rig) and fires Died. Idempotent.

The zombie object is not destroyed here — the owner is expected to call Zombie:Destroy after the death sequence has played out.

GetTarget​

</>
Zombie:GetTarget() → ZombieTypes.ZombieTarget?

Returns the zombie's current target, or nil when it has none. The target is selected by the Seek/Chase states according to targetMode.

GetPosition​

</>
Zombie:GetPosition() → Vector3

Returns the world position of the underlying rig.

GetModel​

</>
Zombie:GetModel() → Model

Returns the rig model this zombie drives.

Destroy​

</>
Zombie:Destroy() → ()

Tears the zombie down: stops the active state (skipped when already in Death, which owns its own cleanup), destroys the Died signal and destroys the underlying NPC and its rig.
