Router

This item only works when running on the client. Client

The client's UI framework. Every screen in the game is a route — a RouteDescriptor naming a path, a React component, and a few flags that decide how and when that component is rendered.

Routes come in two flavors:

  • Regular routes are mutually exclusive. The reducer keeps a single currentPath, so navigating to "CoinShop" implicitly closes whatever modal was open before it. These are the shops, the inventory modal, the daily-rewards modal — anything that owns the screen while it's up.
  • Portal routes (isPortal = true) are concurrent. Each lives in its own slot in mountedPortals and is rendered alongside the active regular route and every other mounted portal. These are the persistent HUD layers — Root, Hotbar, Toaster, Dialog, Scoreboard, Vote.

Portals auto-mount at init. Router.init walks the descriptor list and seeds mountedPortals with an entry for every isPortal descriptor unless it opts out with autoMountPortal = false. In practice this means the HUD is up from the first render and nothing has to explicitly mount it.

Wiring

Client.luau builds the descriptor list and hands it to App, which renders Router.Provider. The Provider calls Router.init once through React.useReducer, then publishes two contexts: the state and a memoized NavigationApi whose methods are thin dispatch wrappers. Views reads both contexts through the hooks and renders the active route plus each mounted portal. 

Client.luau  --routes-->  App  -->  Router.Provider
                                     |- StateContext  (RouterState)
                                     `- NavContext    (NavigationApi)
                                                  |
                                     Views --------'  renders
                                       |- current regular route (0 or 1)
                                       `- every mounted portal (0..n)

Dispatch and subscribe

There is no bespoke store object — the "store" is this module's pure Router.reducer driven by React's own useReducer. Dispatching an Action produces a new RouterState, React re-renders the two context providers, and any component using Router.useCurrentRoute, Router.useCurrentRouteProps or Router.useMountedPortals re-renders with it. Subscription is therefore just context subscription; there is nothing to disconnect.

The reducer is deliberately forgiving: unknown paths, navigating to a portal, and unmounting the default route all warn and return the state unchanged rather than erroring. Router.init is the strict half — it asserts on duplicate paths, on a portal marked isDefault, and on more than one default route.

Navigating

local Router = require(ReplicatedFirst.App.Router)

local function SomeButton()
	local nav = Router.useNavigation()

	return e("TextButton", {
		[React.Event.Activated] = function()
			nav.navigate("CoinShop", { tab = "gems" })
		end,
	})
end

Free-form props handed to a route's component when it renders. Passed through navigate / mount and stored verbatim in the state — the Router never inspects them.

RouteDescriptor​

</>
interface RouteDescriptor {
path: string--

Unique key used to navigate/mount. Duplicates assert at init

component: React.ComponentType<RouteProps>--

Rendered by Views with the route's props

isDefault: boolean?--

Regular routes only. Starts active, cannot be unmounted

isPortal: boolean?--

Renders concurrently with the active route and other portals

autoMountPortal: boolean?--

Portals only. Set false to stay unmounted until asked

}

Declares one route. The full list lives in src/Client/App/Client.luau and is handed to Router.Provider at mount.

isPortal is the important flag: portal routes render concurrently in their own slots, regular routes share a single mutually-exclusive slot. isDefault picks the regular route that is active from the first render and can never be unmounted; it is invalid on a portal.

RouterState​

</>

Every declared route, keyed by path

currentPath: string?--

The one active regular route, or nil when the slot is empty

currentProps: RouteProps?--

Props for the active regular route

mountedPortals: {[string]: RouteProps}--

Path -> props for each concurrently mounted portal

}

Everything the Router knows, rebuilt on each reducer transition and published through Provider.StateContext.

NavigationApi​

</>
interface NavigationApi {
navigate: (
path: string,
props: RouteProps?
) → boolean--

Swap the regular-route slot

mount: (
path: string,
props: RouteProps?
) → boolean--

Mount a portal (or navigate, for a regular route)

unmount: (path: string) → boolean--

Unmount a portal, or clear the regular-route slot

navigateToDefault: () → boolean--

Navigate to the isDefault route, if one exists

}

The imperative half of the Router, obtained with Router.useNavigation(). Every method is a dispatch wrapper and returns immediately — the boolean reports that the action was dispatched, not that the transition was valid. Rejected transitions surface as a warn from the reducer.

navigateToDefault is the exception: it scans the descriptor list itself and returns false when no route is flagged isDefault.
