ItemTypes

Shared shape of everything the game treats as an "item": shop stock, inventory records, placeable props, seeds and crops, animals, and cosmetic skins.

Every item type starts from BaseItem and intersects extra fields onto it, so a field documented on BaseItem means the same thing everywhere. Concrete item tables live in the src/Shared/Data/Items/ and src/Shared/Data/Cosmetics/ registries and are keyed by item id; those registries are what the shop and inventory read at runtime. The prop, seed, crop, animal and egg shapes only type the flag-gated Base classes; no items of those kinds ship in the registries.

The *ItemData variants exist to tighten optional BaseItem fields into required ones once the registry has filled in defaults — author data against PropItem, consume it as PropItemData.

PropItem​

</>
interface PropItem {
rarity: RarityData.Rarity--

Required for props, unlike on BaseItem

buildTime: number?--

Seconds the prop takes to build

upgrades: {PropUpgradeInfo}?--

Levels this prop can be upgraded through

useUpgradePrompt: boolean?--

Show the upgrade prompt when a player is nearby

immovable: boolean?--

Disables the move tool for this prop

destructionPrice: number?--

Cost to remove the prop, if set

destroyTime: number?--

Seconds the prop takes to destroy

stashable: boolean?--

Prop can be stashed back into the player's inventory

propDisplayPaths: {{
path: string,
label: string,
formatter: ((any) → string)?
}}?--

Stats surfaced on the nearby-prop display

}

A BaseItem that can be placed on a base.

This type exists to make the shape easier to read while authoring prop item data, where several BaseItem fields are still optional. Use PropItemData everywhere else.

Removing a prop requires meeting the same gates as buying it — levelRequirement, townLevelRequirement, purchasePrice and so on.

propDisplayPaths entries are paths relative to the data's props table. Lookup walks the current level's upgrade info down to level 1 for a value; if the next level also defines that path, the display shows "currentValue -> nextValue".

destructionPrice is inert

The destructionPrice field and the FeatureFlags.ChargeForDestruction flag that would govern it both exist, but nothing in the codebase currently reads either one. Removing a prop is free today.

interface SeedItemData {

Seconds from seed to flower (usually within seconds)

maturityTime: number--

Seconds until the crop is ready to harvest

Seconds; must be less than maturityTime, defaults to half of it

Seconds after maturity before withering; absent means it never withers

Id of the crop this seed grows into

produceYield: number?
}?--

}

A plantable seed and its growth timings.

Supplying cropTreeData turns the seed into a crop tree: instead of being harvested once, it repeatedly yields produce every produceGrowTime seconds, indefinitely unless produceYield caps it.

SkinSurfaceAppearance​

</>
interface SkinSurfaceAppearance {
ColorMap: string?
MetalnessMap: string?
RoughnessMap: string?
NormalMap: string?
}

PBR map set baked onto the default skin mesh via a SurfaceAppearance child.

A mesh-swap cosmetic skin has three visual paths, in order of precedence:

  1. Hand-authored MeshPart at ReplicatedStorage.Assets.Cosmetics.<itemId> (escape hatch for skins with custom geometry).
  2. surfaceAppearance — this type. Use for metals, gems, glossy looks.
  3. texture — a single image asset id set as the MeshPart's TextureID. Use for plain painted/diffuse looks.

Both (2) and (3) are baked into assets/shared/Cosmetics.rbxm by the Lune build tool; SurfaceAppearance can't be assigned at runtime.

A mesh-swap cosmetic skin, or a gear skin when subtype names a gear slot. See the comment on SkinSurfaceAppearance for the three visual paths and their order of precedence; gear skins instead take their model from Assets.Cosmetics.<itemId> and may override the gear config through gear.
