PropTypes

Types for placed props and the replicas that mirror them to clients.

Two layers meet here. Saved types (Saved...) are what gets written to the player's profile through BaseUtil. Replica types are the runtime view Replica pushes to clients — they carry the saved data plus fields that only make sense while the world is loaded, like the prop's origin CFrame and hitboxes.

Each replica data type has a matching client and server alias ([BaseReplica] / [BaseReplicaServer]); the server one can mutate, the client one is read-only.

Grid placement relative to the base

Saved prop data; modifying this saves it

isBuilding: boolean--

Prop is mid-build and not yet functional

}

Replicated state of one placed prop.

props writes are persisted

props is not a scratch table — it is the live saved data. Writing to it is how a prop persists state, so avoid stashing per-frame or per-session values there.

interface SavedAnimalPenData {
eggs: {[string]: EggEntry}--

Incubating eggs, keyed by entry id

animals: {[string]: AnimalEntry}--

Live animals, keyed by entry id

drops: {[string]: DropEntry}--

Persisted uncollected drops

lastCollectionTime: number--

Persisted collection time

capacity: number--

Persisted capacity

}

The animal pen's slice of a prop's saved props table. Everything here survives a rejoin, so a pen keeps producing across sessions.

AnimalPenReplicaData​

</>
interface AnimalPenReplicaData {
lastCollectionTime: number--

Mirrors props.lastCollectionTime

drops: {[string]: DropEntry}--

Runtime reference to props.drops

capacity: number--

Mirrors props.capacity

props: SavedAnimalPenData--

Narrows the base props field to the pen's shape

}

PropReplicaData for an animal pen.

The top-level drops, capacity and lastCollectionTime fields are conveniences that point at the same data inside props — they are not a second copy, so do not write one and expect the other to differ.
