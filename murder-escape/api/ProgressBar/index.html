ProgressBar

Wraps the shared Assets.UI.ProgressBar template with a small API for filling it, labelling it, and driving it from a countdown.

Each instance clones the template and holds the resolved child GuiObjects, so callers never touch the template's internal structure. Fill changes tween by default, but skip the tween while the bar is not in the rendered tree — an off-screen bar snaps to its value instead of animating from zero when it appears. 

local bar = ProgressBar.new(Color3.fromRGB(0, 170, 255), "Building", frame, 0)

bar:SetProgress(0.5)
bar:Destroy()

Clones the progress bar template and configures it.

The title label starts hidden and is only shown once a title is set. Passing instanceWrap parents the bar to it; otherwise the bar is created unparented and you must parent bar.root yourself.

SetProgress​

</>
ProgressBar:SetProgress(
progress: number,--

Fill fraction from 0 to 1

forceSet: boolean?--

Snap instead of tweening

) → ()

Fills the bar to progress, tweening over 0.2s.

The value is not clamped — pass something already within 0 to 1. The tween is skipped entirely when the bar is not yet parented into PlayerGui or Workspace, and forceSet skips it on demand.

UpdateProgressAndTime​

</>
ProgressBar:UpdateProgressAndTime(
startTime: number,--

Server time the window opened

endTime: number--

Server time the window closes

) → ()

Sets both the fill and the in-bar text from a time window, using Workspace:GetServerTimeNow() as the clock.

Progress is the fraction of the window elapsed, clamped to 0-1, and the text is the remaining time at a sensible granularity: 2d 4h, 3h 20m, or 1m 5s.

This is a single update, not a subscription — call it on a loop (a Heartbeat connection or a one-second timer) to keep the countdown live.

Destroy​

</>
ProgressBar:Destroy() → ()

Removes the bar from the UI.

Destroys the wrapper, not just the bar

When the bar was constructed with an instanceWrap, that instance is destroyed rather than the bar alone — anything else parented inside it goes too.
