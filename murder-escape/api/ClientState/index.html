ClientState

This item only works when running on the client. Client

The client's single shared store. Nearly every component and controller reads from it, so treat it as public API: renaming or removing a field breaks callers spread across the whole client tree.

Each field (other than version and currentFTUEStep) is a State object — read with :Get(), write with :Set(), subscribe with .Changed. React components generally wrap those subscriptions in an effect and mirror the value into useState.

Who writes what

Writers are deliberately few; if a component is calling :Set() on anything here, it is probably a layering mistake.

  • playerData — DataController, from the Profile Replica.
  • coins, xp — StatsController, projected out of playerData.stats.
  • friendBoost — SocialController, from the friends-in-server poll.
  • ready — Entry.client.luau, right after it dispatches READY.
  • hotbarSlots, currentlySelectedHotbarItemRecord — the hotbar feature.
  • activeBlurs, inVehicle, currentFTUEStep — their respective features.

See ClientStateFields for the individual fields.

interface ClientStateFields {
version: string--

Build version, copied from ReplicatedStorage.Version at require time

ready: State<boolean>--

False until the client has finished booting and dispatched READY

playerData: State<ProfileTypes.ProfileData>--

Mirror of the Profile Replica. Seeded from DataTemplate so it is never nil

coins: State<number>--

playerData.stats.coins, projected so coin-only consumers don't wake on every profile change

xp: State<number>--

playerData.stats.xp, projected the same way

activeBlurs: State<{string}>--

Ids of the UI layers currently requesting a background blur; blur is on while non-empty

hotbarSlots: State<{[number]: InventoryData.HotbarSlot}>--

Hotbar contents keyed by slot index

hotbarVisible: State<boolean>--

False in the lobby; round/game code sets true to show the hotbar

currentlySelectedHotbarItemRecord: State<{itemRecord: Types.ItemRecord?}>--

The equipped hotbar item, wrapped so "nothing equipped" is a table with a nil field rather than a nil state

friendBoost: State<number>--

Multiplier earned from friends in the server, per BoostData.getBoostPerFriend

inVehicle: State<boolean>--

True while the local player is driving or riding

currentFTUEStep: number?--

Index of the active first-time-user-experience step, or nil when the FTUE is not running

}

Every field on the ClientState singleton.

version is read once at require time from the Version value under ReplicatedStorage — it is a plain string, not a State, and never changes. currentFTUEStep is likewise a plain value rather than a State, so it cannot be subscribed to; read it directly.
