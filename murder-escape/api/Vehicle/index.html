Vehicle

This item only works when running on the server. Serverdormant

Manages a single vehicle instance: spawning, seat occupancy, collision setup, despawn timer, and cleanup.

One instance wraps one car model. Instances are registered in a module-level Model → Vehicle cache so any code holding just the model can recover the wrapper with Vehicle.getCar — that is how VehicleService gets from its player → Model map to the behaviour on this class.

Network ownership is the whole design

Physics is simulated by the driver's client. Taking the driver's seat hands that client network ownership of the assembly; leaving it reclaims ownership for the server. The reclaim sequence in Vehicle:OnOccupantChanged is deliberately fussy — sever the character's weld first, zero the wheel velocities the client was driving, then un-anchor → SetNetworkOwner(nil) → re-anchor, and only 0.1s later zero the assembly velocity and release. Each step exists to stop a specific artefact: dragging the character with the car, wheels spinning forever at their last commanded velocity, and the vehicle clipping through the floor as the server resolves a position it did not simulate.

Collision groups

Set up once at require time: CarDetail ignores both the body and the wheels, and CarWheel ignores CarBody — the constraints already position the wheels, so letting them collide with the body only produces jitter.

Suspension

Spring stiffness and damping are computed from the assembly's real mass, one frame after parenting (task.defer, because AssemblyMass is not meaningful until then). Stiffness is sized so the car sags exactly SUSPENSION_TARGET_SAG studs at rest, and damping from the standard 2ζ√(km) relation at SUSPENSION_DAMPING_RATIO. Tuning against measured mass rather than fixed numbers means adding attachments or passengers does not bottom the car out.

Ejection

Every exit path routes through the same helper, which projects the exit direction onto the XZ plane (so a flipped car does not eject downward), raycasts for ground, falls back to the vehicle's roof if there is none, and clamps to MIN_EJECT_Y as a last resort against dropping players through the world.

Gated by FeatureFlags.Vehicle — disabled by default; per-project forks enable it deliberately.

new​

</>
Vehicle.new(
config: VehicleConfig?--

Defaults to an unowned vehicle with no placement

) → Vehicle?

Spawns a vehicle, or returns nil if it cannot be placed.

Placement is either the supplied spawnCFrame or, for an owned vehicle, resolved from the owner's character: a point SPAWN_DISTANCE studs ahead is raycast down for ground, and a temporary box the size of the car's bounding box is overlap-tested for clearance. Either failing returns nil. This repeats the check VehicleController.spawn already ran on the client, because the client's answer is advisory.

Setup, in order:

  • Clone and tag the model, stamp OwnerId and a SpeedMultiplier of 1.
  • Nudge the driver's SeatWeld via the seat attachment so the character sits at the wheel rather than at the seat part's raw origin.
  • Wire seat Occupant listeners and the enter prompt (itself debounced to one entry per second).
  • Assign collision groups: Details → CarDetail, DBO parts → CarBody, and every part carrying a CylindricalConstraint attachment → CarWheel with high-friction physical properties so the wheels actually grip.
  • Parent to the Workspace, then task.defer the mass-derived suspension tuning described on Vehicle.

Returns nil without side effects if the model has no DriverSeat.

StartTimer​

</>
Vehicle:StartTimer() → ()

Arms the idle-despawn timer, which runs DESPAWN_TIME after the vehicle is spawned or vacated. Vehicle:StopTimer cancels it when someone gets in.

NOTE

The timer body is commented out, so the vehicle is never actually despawned — the scheduling is live but the effect is disabled. Re-enabling it requires calling back into VehicleService, which is why it was stubbed: this class does not import that service.

StopTimer​

</>
Vehicle:StopTimer() → ()

Cancels a pending idle-despawn timer, if any.

OnOccupantChanged​

</>
Vehicle:OnOccupantChanged(
seat: VehicleSeat--

The seat whose occupancy changed

) → ()

Handles a seat's Occupant changing — the voluntary-exit path, as opposed to the forced Eject* methods.

The enter prompt is toggled to match occupancy, and the idle-despawn timer is stopped while someone is driving and restarted once the vehicle empties.

A departing driver triggers the full handover described on [Vehicle]: fire StopControl, brake, sever the character's weld, zero the wheel velocities the client was commanding, reclaim network ownership through the un-anchor/set/re-anchor dance, place the character on the ground to the car's left, zero their velocity so they do not inherit the car's momentum, and stop the idle engine sound.

A departing passenger is simply placed on the right-hand side.

Either way the character's collision is restored on the way out.

EnterDriverSeat​

</>
Vehicle:EnterDriverSeat(player: Player) → ()

Seats a player as the driver. Refuses if the seat is taken, or if ownerOnly is set and they are not the owner.

Grants the player network ownership of the assembly before seating them — this is what makes their client the physics authority, and the vehicle must be un-anchored first for the grant to take.

EnterPassengerSeat​

</>
Vehicle:EnterPassengerSeat(player: Player) → ()

Seats a player as the passenger. Refuses if there is no passenger seat or it is occupied. Passengers get no network ownership and no control.

getSeatedPlayers​

</>
Vehicle:getSeatedPlayers() → {Player}

Every player currently seated in this vehicle: the driver (if any) followed by the passenger. Only players who boarded through the enter handlers are known — engine touch-seated characters are untracked.

AttachAttachment​

</>
Vehicle:AttachAttachment(
attachmentType: string,--

Slot name; also the attachment point prefix

attachmentModel: Model--

Template to clone; needs a PrimaryPart

) → boolean--

Whether it was attached

Clones attachmentModel onto the vehicle at the platform attachment named <attachmentType>Attachment, welds it to the platform and records it in the slot.

Refuses if the slot is already filled — VehicleService:equipAttachment removes the incumbent first — and warns and refuses if the model has no PrimaryPart or the named attachment point does not exist.

Every part of the clone is put on the CarBody collision group so an attachment cannot collide with the car it is bolted to.

SetSpeedMultiplier​

</>
Vehicle:SetSpeedMultiplier(
multiplier: number--

0..1

) → ()

Sets the vehicle's SpeedMultiplier attribute, which the driving client reads every frame to scale its top speed. Using an attribute rather than a remote means the change replicates on its own and applies immediately.

Clamped to 0..1, so this can only slow a vehicle down; 0 is a full stop. No-ops if the vehicle has been unparented.

Brake​

Stops the vehicle by setting its speed multiplier to 0. The vehicle stays braked until something restores the multiplier — entering the driver's seat resets it to 1.
