BaseGameMode

This item only works when running on the server. Serverdormant

Full featured round base class for any type of round based experience.

Everything a round needs — players, teams, scores, rewards, gamepass multipliers, map loading, lighting, spawning, the countdown, and the end-of-round payout — lives here. A concrete game mode subclasses this and supplies only its own rules.

The subclass contract

A game mode is a table that inherits from BaseGameMode and is constructed with a GameModeConfig. It implements at most two methods, both optional:

Method When it runs Purpose
Init after players are gathered, teams are set up and lives are assigned, but before playing is set and before auto-spawn one-time round setup: wire signals, prepare the map, place props
Play after spawning, once the round is live the round itself — must yield for the whole round

Both are called by BaseGameMode:Start, each wrapped in a try so a throwing mode warns rather than wedging the server. When Play returns, the round is over: Start calls BaseGameMode:Stop itself. A mode that omits Play gets the default behaviour of a plain BaseGameMode:GameCountdown for config.roundTime. 

local MyMode = setmetatable({}, { __index = BaseGameMode })
MyMode.__index = MyMode

function MyMode.new(props)
	local self = setmetatable(BaseGameMode.new(config, props), MyMode)
	return self
end

function MyMode.Init(self)
	-- one-time setup; the round is not live yet
end

function MyMode.Play(self)
	-- yields for the whole round
	self:GameCountdown(nil, function()
		-- runs once a second; return false to end the round early
		return true
	end)
end

Everything else — Setup, Start, Stop, Destroy — is driven by GameService and should not be overridden.

Round lifecycle

  1. new — merges the mode's config over MinigameConfig.default, picks a map, calls BaseGameMode:Setup to clone it in, snapshots the player list, and starts a background gamepass scan. Late joiners are caught by a PlayerAdded handler that re-sends the countdown, music and round-start state.
  2. Start — refreshes the player list, drops anyone dead or characterless, assigns lives, hides cosmetics, sets up teams, runs Init, flips playing, auto-spawns if configured, then runs Play.
  3. The round — the mode yields inside Play. Exits are: Play returning, BaseGameMode:GameCountdown running out or its condition returning false, BaseGameMode:PlayerCheck failing (too few players, or everybody has won), or an explicit Stop.
  4. Stop — pays out winners, broadcasts the summary, reloads characters, restores lighting, destroys the map, and calls Destroy.

Winner semantics

winners is a UserId → Player map, not a list of survivors. A mode declares winners explicitly with BaseGameMode:AddWinner; nothing is implicit. Two consequences worth internalizing:

  • A player can be dead and still win — winning is recorded once and is not revoked by dying, only by BaseGameMode:RemoveWinner.
  • Because BaseGameMode:PlayerCheck ends the round once every remaining player is a winner, adding the last winner ends the round. Modes where everyone eventually wins (races, collection games) must set config.disableWinnerCheck or they will terminate the instant the field fills up.

Only winners are paid. Scores are tracked for everyone but the payout loop in Stop iterates winners, so a non-winner banks nothing.

Scoring and rewards

Two parallel notions:

  • Score — BaseGameMode:AddPoint, a raw number used for end-of-round ranking.
  • Rewards — BaseGameMode:Reward, a per-player { stat → amount } map (coins, xp, kills, …) that becomes the actual payout. Any stat listed in MinigameConfig.pointValues also contributes to score at its configured rate, so most modes only call Reward and let score follow.

At payout, multipliers stack in this order: the mode's config.reward.multiplier × the player's BaseGameMode:SetRewardMultiplier value, then Roblox Premium on xp, then every gameplay gamepass the player owns. Rankings are assigned by sorting on final score.

Teams

Opt-in. Set config.teams to a { name → Color3 } map and Start calls BaseGameMode:TeamSetup automatically; otherwise self.teams stays nil and the round is a free-for-all. Team membership lives in two places that must stay in sync — the teams[name].players list and the character's TeamTag attribute — which is why BaseGameMode:TeamPush is the only supported way to move a player. Players may also join and leave teams at runtime via the TEAM_JOIN/TEAM_LEAVE actions handled in the constructor.

Gated by FeatureFlags.Minigames — disabled by default; per-project forks enable it deliberately.

Functions​

new​

</>
BaseGameMode.new(
config: MinigameTypes.GameModeConfig,--

The mode's own config

props: MinigameTypes.GameModeProps--

Per-round overrides, e.g. a forced map

) → BaseGameMode

Constructs a round. Called by a subclass's own .new, which then re-setmetatables the result onto itself.

Merges config over MinigameConfig.default, picks the map (props.map if given, otherwise a random entry from config.maps), and calls BaseGameMode:Setup to clone it into the world. The round is not live yet — BaseGameMode:Start does that.

It also installs three lifetime handlers, all owned by the round's Maid:

  • PlayerAdded — a player joining mid-round waits for their character, then receives the current countdown, the game music cue and the round-start state, so a late joiner's HUD matches everyone else's.
  • PlayerRemoving — removes the leaver from the round and their team.
  • TEAM_JOIN / TEAM_LEAVE — lets a client switch teams mid-round; joining also spawns the player at their new team's spawn.

Gamepass ownership is scanned on a background thread rather than inline, because GamePass.has yields per player and the round must not block on it. The scan only runs if the lobby met the minimum player count.

SetLighting​

</>

Applies the mode's config.lighting block to the game's Lighting service — ambient, brightness, clock time and the atmosphere settings. No-ops when the mode declares no lighting.

Called on map setup and again in BaseGameMode:Stop to put the lighting back.

CAUTION

The restore in Stop calls this same method, so it re-applies the mode's lighting rather than the lobby's. A mode that changes lighting leaves it changed until the next mode overwrites it.

Spawn​

</>
BaseGameMode:Spawn(data: {
players: Player | {Player},
spawns: Folder | BasePart | {BasePart},
loadCharacter: boolean?
}) → {Player}--

Players successfully placed

Places one or more players at spawn points and returns the ones actually placed — a player who left, died during the call, or whose character could not be built is skipped, so always check the returned list before firing follow-up logic like PlayerSpawned.

spawns accepts a single part, a list of parts, or a folder (whose BasePart children are used); each player independently draws a random one. With loadCharacter set, a fresh character model is built and assigned, which is how respawns work; otherwise the existing character is teleported.

Players are scattered around their spawn point by a random offset, read from the spawn's SpawnOffset attribute (or a legacy Offset value object), defaulting to ±4 studs — this is what stops a team spawning inside itself.

Each spawned character is stamped with the round's attributes: Spawned, the RoundTag round id, and the mode's HealthRegen, UseFallDamage and KeepRagdollInWorld settings. A Died listener is attached that routes into BaseGameMode:HandlePlayerDeath.

Aborts and returns an empty list if the round stops mid-call, since character creation yields.

Yields when building characters.

RemovePlayer​

Removes a player from the round (and from team, if given) and rebroadcasts the alive count.

This drops them from players but does not clear their winner entry, score or pending rewards — a player who has already won still gets paid if they leave, and their character is not touched.

HandlePlayerDeath​

</>
BaseGameMode:HandlePlayerDeath(
player: Player--

The player who died

) → ()

Handles a player dying. Wired up automatically by BaseGameMode:Spawn; modes rarely call it directly.

First, kill credit: if the character carries a KillTag attribute naming a killer's UserId, that killer is rewarded one kills point and PlayerDied fires with both players. The tag is cleared so a body cannot be credited twice.

Then a life is spent. With lives remaining the player waits config.respawnTime, respawns at their team's spawn with a fresh character, and is told their new life count. With none left they are removed from the round, moved to inactivePlayers, and sent PLAYER_INACTIVE — they stay in the world as a spectator rather than being kicked back to the lobby mid-round.

Yields for the respawn delay and character creation.

EnoughPlayers​

</>
BaseGameMode:EnoughPlayers(
broadcastMessage: boolean?--

Announce the shortfall to players

) → boolean

Whether the round still has the globally required minimum number of players (MinigameConfig.minimumPlayers, not the mode's own config.minimumPlayers).

When it fails, it optionally announces the shortfall and — if a map is loaded — stops the round. So this is not a pure predicate: calling it can end the round.

Call it after any yield, since players can leave while a mode is waiting.

PlayerCheck​

</>
BaseGameMode:PlayerCheck() → boolean--

true to continue the round

Whether the round should keep going. Consulted every tick of BaseGameMode:GameCountdown and after every BaseGameMode:AddWinner.

Returns false when the round is not playing, when nobody is left, or when every remaining player is already a winner — the last being the "everyone made it, nothing left to play for" exit. Set config.disableWinnerCheck to skip that test entirely, which is what modes need when every participant is expected to win.

The all-winners test is a loop rather than a #players == #winners comparison, deliberately: players can die and still be winners, so the two counts drift apart and only a membership scan is correct. If any non-winner is found, the round continues provided the mode's own config.minimumPlayers is still met.

Reward​

</>

Accumulates rewards for a player: { coins = 10, xp = 5 } and so on. Values add to whatever the player has already earned this round.

AddWinner​

</>
BaseGameMode:AddWinner(players: Player | {Player}) → ()

Declares one or more players winners of the round. Winning is what makes a player eligible for payout at Stop.

Each new winner is immediately granted the mode's configured reward.coins and reward.xp. Players already recorded as winners, or who are no longer in the round, are skipped.

CAUTION

This can end the round. After each winner is added, BaseGameMode:PlayerCheck runs, and if every remaining player is now a winner the round stops immediately. Modes where all participants eventually win must set config.disableWinnerCheck.

Loop​

</>
BaseGameMode:Loop(
fn: () → boolean?--

Return truthy to keep looping

) → ()

Runs fn repeatedly on a new thread until it returns a falsy value or the round stops. Returns immediately — this does not yield the caller, so a mode's Play cannot use it as its only body without also yielding some other way.

CAUTION

fn must yield at least one frame per iteration. It is called in a tight while loop with no implicit wait, so a non-yielding function hangs the thread. 

self:Loop(function()
	task.wait(1)
	return self:PlayerCheck()
end)

GameCountdown​

</>
BaseGameMode:GameCountdown(
duration: number?,--

Seconds; defaults to config.roundTime

conditionCheck: ((deltaTime: number) → boolean)?--

Per-second check; return false to end early

) → boolean--

true if the countdown completed with the condition intact

Runs the round timer and yields until it finishes. The usual body of a mode's Play.

Counts down from duration (defaulting to config.roundTime), starting the client-side display via BaseGameMode:Countdown and stepping self.time every frame. conditionCheck — if given — is called roughly once a second, not every frame, and returning anything but true ends the countdown early.

It exits when any of these becomes true: the condition failed, the time ran out, BaseGameMode:PlayerCheck said stop, or the round is no longer playing. The return value distinguishes the first case from the rest.

Warns and returns immediately if the round has no config.

Start​

</>
BaseGameMode:Start() → ()

Runs the round from beginning to end and yields for its entire duration. Called by GameService; modes should not call it.

In order:

  1. Refresh the player list (people join during voting), and bail out via Stop if the mode's minimum is not met.
  2. Per player: drop anyone dead or characterless, assign lives, optionally hide nameplates, stamp the RoundTag, and hide their equipped cosmetic. Dropping players re-checks the minimum as it goes.
  3. Build teams from config.teams if present.
  4. Call the subclass's Init, wrapped so a throw only warns.
  5. Set playing, then auto-spawn if config.autoSpawn — per team into Spawns/<teamName> when teams exist, falling back to the shared Spawns folder if the map has no team spawns.
  6. Call the subclass's Play (which yields for the round), or run a default BaseGameMode:GameCountdown if the mode does not define one.
  7. Stop, unless the round already stopped itself.

Yields for the whole round.

Stop​

</>
BaseGameMode:Stop() → ()

Ends the round: pays out winners, shows the summary, and cleans up. Safe to call from anywhere, including from inside a mode — BaseGameMode:Start checks whether the round already stopped before calling it again.

World teardown runs on its own thread with a 3-second grace period so players see the final moment before the map vanishes; lighting is restored and the map destroyed after it.

Then, on the main path: fire Stopping, clear playing, fire Stopped, destroy the Maid (killing every round connection), broadcast ROUND_END and stop the music. Cosmetics are restored for active and inactive players alike, and every character carrying a RoundTag is reloaded.

Payout, after a short beat, per winner:

  1. Apply config.reward.multiplier × the player's own BaseGameMode:SetRewardMultiplier.
  2. Apply the Premium multiplier to xp for Premium members.
  3. Apply every gameplay gamepass multiplier the player owns, per stat.
  4. Emit an EndWinner with the final rewards and score.

Winners are then sorted by score to assign ranks, the whole table is broadcast as GAME_ROUND_SUMMARY (each client also receiving its own local rewards), and coins, xp, points, kills and a win are written to each winner's profile.

Finally calls BaseGameMode:Destroy.

Yields for several seconds across the teardown.

Destroy​

</>
BaseGameMode:Destroy() → ()

Final teardown: fires Destroying and destroys the Maid. Guarded so it only ever runs once, since BaseGameMode:Stop calls it and callers may too.

Does not touch the map or the players — BaseGameMode:Stop owns that.
