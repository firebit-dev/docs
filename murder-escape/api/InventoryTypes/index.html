InventoryTypes

Types for the inventory and hotbar UI, plus the payloads for selling from it.

Most of this file describes UI bookkeeping rather than saved data: the resolved GuiObjects behind one inventory slot, the drag-and-drop state machine, and the hotbar's per-slot record. The player's actual items are Types.ItemRecords and live on the profile — these types only reference them.

interface ButtonData {

The specific inventory stack this button shows

itemId: string--

Item id of that stack

button: ItemButtonData--

Resolved GuiObjects for the slot

dragging: boolean?--

This button is the one currently being dragged

hovering: boolean--

Cursor is over this button

}

A slot bound to a particular item stack — ItemButtonData plus what it is currently displaying and its interaction state.

DragState​

</>
interface DragState {
isDragging: boolean--

A drag is in progress

draggedItem: ButtonData?--

Slot being dragged

clonedButton: Frame?--

Floating copy that follows the cursor

originalFrame: Frame?--

Frame left behind in the grid

startPosition: Vector3?--

Cursor position when the drag began

dragMaid: Maid.Maid?--

Cleans up connections and the cloned frame

offsetX: number?--

Cursor offset within the dragged frame

offsetY: number?
isMouseDown: boolean?--

Button is held, which may not yet be a drag

hoveredButton: ButtonData?--

Slot the drag would drop onto

currentPosition: Vector3?--

Latest cursor position

}

Mutable state for one drag-and-drop gesture in the inventory grid.

isMouseDown and isDragging are separate on purpose: a press only becomes a drag once the cursor has moved far enough, so a click that never moves still reads as a click. dragMaid owns everything created for the gesture — destroying it cancels the drag cleanly.

HotbarSlotData​

</>
interface HotbarSlotData {
slotIndex: number--

1-based position in the hotbar

itemButtonData: ItemButtonData--

Resolved GuiObjects for the slot

itemRecord: Types.ItemRecord?--

Item occupying the slot; nil when empty

hovering: boolean?
}

One hotbar slot. Unlike an inventory slot, a hotbar slot exists whether or not anything is in it, so itemRecord is optional.

InventorySellItemPayload​

</>
interface InventorySellItemPayload {
recordId: string--

Inventory stack to sell from

quantity: number--

How many to sell out of that stack

}

Sells part or all of one stack. The payout is resolved server-side from the item's resaleValue, so no price is sent.

SellItemData​

interface SellItemData {
recordId: string--

Inventory stack to sell from

quantity: number--

How many to sell out of that stack

}

One line item within a bulk sell. Structurally identical to InventorySellItemPayload, but it is an element of a request rather than a request itself.

</>
interface InventorySellAllPayload {
items: {SellItemData}--

Every stack to sell, with quantities

}

Sells many stacks in one round trip.
