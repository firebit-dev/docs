BaseUtil

dormant

Author: Javi M (dig1t)

Shared vocabulary for the base (player farm) system: the constants both realms must agree on, the persisted data schema, and the pure maths that converts between world CFrames and plot grid coordinates. It holds no state and creates no props — PropBaseClass and the Base service do that.

Coordinate model

A base owns one or more plots; a plot is a GRID_UNITS × GRID_UNITS square of GRID_UNIT-stud cells. Prop positions are stored as a PositionData — plot-relative X/Y (Y being world Z) plus a rotation R constrained to multiples of ROTATION_STEP. Nothing persists world CFrames, so a base can be re-instantiated anywhere in the world.

getPositionDataFromPivot is the one-way funnel from a dragged pivot into that grid: it takes the pivot into the plot's object space, snaps translation to the nearest half stud and yaw to the nearest ROTATION_STEP, and normalizes 360° back to 0. getOffsetFromPositionData is the inverse.

CAUTION

getPositionIndex and positionIndexToPositionData are not inverses of each other — the former is 1-based on Y (x + GRID_UNITS * (y - 1)) while the latter reconstructs y as floor(index / GRID_UNITS) + 1 and x via a modulo that maps a full row back to 0. Round-tripping a position through them does not return the original.

Containers and tags

Two Workspace containers are created on the server and waited for on the client: PROP_CONTAINER (client-side visual models, persistent so it never streams out) and HITBOX_CONTAINER (server-side bounding boxes, one sub-model per base). CollectionService tags — BASE_TAG, PLOT_TAG, PROP_TAG, PROP_MODEL_TAG, GRID_FLOOR_TAG, PROP_IGNORE_TAG — are how controllers find those instances without holding references, and the two *_REPLICA_CLASS strings are the Replica class names the base and its props register under.

Persistence

getDataTemplate produces a fresh BaseData for a new player and reconcileBaseData is the forward-migration pass: it fills in any top-level key the template has and the save does not, returning whether it changed anything so the caller can decide to write. It is shallow by design — nested plot and prop records are not reconciled.

Gated by FeatureFlags.BaseEnabled — disabled by default; per-project forks enable it deliberately.

Functions​

roundToNearestHalf​

</>
BaseUtil.roundToNearestHalf(value: number) → number

Snaps a stud value to the nearest 0.5. Half-stud resolution — rather than whole GRID_UNIT cells — is what lets props sit centred between grid lines as well as on them.

roundToNearestDegree​

</>
BaseUtil.roundToNearestDegree(
rotation: number--

Yaw in degrees

) → number

Snaps a yaw in degrees to the nearest multiple of ROTATION_STEP (90°). Note this can return 360 for inputs near a full turn — callers that store the result normalize it back to 0.

getDefaultFarmName​

</>
BaseUtil.getDefaultFarmName(player: Player) → string

Returns the default farm name for a player ("<DisplayName>'s Farm").

On the server the name is run through text filtering before being returned, since it embeds a user-controlled display name and ends up on a public sign. On the client filtering is unavailable, so the raw name is returned — that path is for optimistic UI only and must not be persisted.

Yields on the server for the filter call.

getDataTemplate​

</>
BaseUtil.getDataTemplate(player: Player) → BaseData

Builds a fresh BaseData for a player who has no base yet — a new id, the default farm name and style, no plots, and the starting lootCartBonus.

Also serves as the source of truth for BaseUtil.reconcileBaseData, so adding a key here is what makes it appear on existing saves.

reconcileBaseData​

</>
BaseUtil.reconcileBaseData(
player: Player,--

Used to build the comparison template

data: BaseData--

Mutated in place

) → boolean--

Whether anything was added, so the caller can skip a write

Forward-migrates a loaded base in place: any top-level key present in BaseUtil.getDataTemplate but missing from data is filled in from the template.

Shallow by design — nested plot and prop records are left untouched, since those have their own per-class schemas. Existing values are never overwritten, so this is safe to run on every load.

getPositionIndex​

</>
BaseUtil.getPositionIndex(
x: number,--

Column, 1-based

y: number--

Row, 1-based

) → number

Flattens a 1-based grid coordinate into a single PositionIndex (x + GRID_UNITS * (y - 1)).

CAUTION

BaseUtil.positionIndexToPositionData is not a true inverse of this — see the caution on BaseUtil.

positionIndexToPositionData​

</>
BaseUtil.positionIndexToPositionData(index: number) → PositionData

Expands a flattened grid index back into a PositionData with zero rotation.

CAUTION

Not an exact inverse of [BaseUtil.getPositionIndex]: an index that lands on the last column of a row (index % GRID_UNITS == 0) comes back as column 0 of the next row. Do not rely on a round trip.

getPositionDataFromPivot​

</>
BaseUtil.getPositionDataFromPivot(
origin: CFrame,--

The plot's origin

pivot: CFrame--

World pivot of the prop being placed

) → PositionData

Converts a world pivot into snapped, plot-relative PositionData — the single funnel every placement goes through.

Takes pivot into origin's object space, snaps X and Z to the nearest half stud and the yaw to the nearest ROTATION_STEP, and normalizes a 360° result back to 0 so rotations compare equal.

getOffsetFromPositionData​

</>
BaseUtil.getOffsetFromPositionData(position: PositionData) → (
CFrame,--

Translation

CFrame--

Rotation

)

Inverse of [BaseUtil.getPositionDataFromPivot]: expands stored grid coordinates back into a translation and a rotation, returned separately so callers can compose them around the prop's own pivot offset rather than being handed a pre-multiplied CFrame.

isPositionDataEqual​

</>
BaseUtil.isPositionDataEqual(
position1: PositionData,
position2: PositionData
) → boolean

Whether two placements are the same. Used by PropBaseClass:MoveTo to discard no-op moves.

Rotation is compared by absolute value, so -90 and 90 count as equal even though they are visually different. That is deliberate for the intended shapes but means a 180° flip of an asymmetric prop can be treated as no move.

validatePositionData​

</>
BaseUtil.validatePositionData(position: PositionData) → boolean

Shape-checks a PositionData that arrived from a client: all three fields must be numbers and R must be an exact multiple of ROTATION_STEP.

This validates the format only — it says nothing about whether the position is inside the plot or free of collisions. Those checks live with the caller.

formatModelPoints​

</>
BaseUtil.formatModelPoints(
model: Model?,--

The style model; warns and returns nil if absent

style: string--

Style name, used in the assertion messages

) → Points?

Extracts the named anchor points from a base style model and returns them as Points, keyed by part name. Parts nested one folder deep are flattened to <Folder>__<Child> — which is how per-plot points end up as Plot__1, Plot__2 and so on.

Every value is the part's bottom surface, so callers can place directly on it.

The Points folder is destroyed afterwards: the markers are build-time metadata and must not survive into the live base.

Asserts that Spawn, LootCart and a point for every entry in PLOTS exist, so a mis-authored style model fails loudly at load rather than producing a base with unreachable plots.

Yields waiting for the Points folder.

generatePlot​

</>
BaseUtil.generatePlot(
origin: CFrame--

Plot origin

) → (
BasePart,--

The grid floor

{[PositionIndex]: BasePart}--

Per-cell parts; presently empty

)

Builds a plot's floor: one invisible GRID_UNITS × GRID_UNITS cell part tagged GRID_FLOOR_TAG, wearing a tiled checker texture that draws the grid rather than instancing a part per cell.

The second return value is the per-cell part map. It is currently allocated but never filled — cells are computed arithmetically, so the map exists for a future implementation that needs addressable cell instances (per-cell highlighting, say). Treat it as empty.

The caller is responsible for parenting the returned floor.

randomizeColorShade​

</>
BaseUtil.randomizeColorShade(color: Color3) → Color3

Jitters a colour's saturation and value slightly (hue is left alone — the variance constant for it is 0) so repeated instances of the same asset do not read as identical clones.

isHitboxIntersecting​

</>
BaseUtil.isHitboxIntersecting(
hitbox: BasePart,--

Hitbox being tested

origin: CFrame?,--

Position to test at; defaults to the hitbox's own

propIdToIgnore: string?--

Prop id to exclude, e.g. the one being moved

) → boolean

Whether a prop hitbox would overlap any other prop hitbox — the collision test that gates placement.

Builds an include filter of every PROP_TAG-tagged part in HITBOX_CONTAINER except hitbox itself, then block-casts a temporary part of the same size at origin (defaulting to the hitbox's own CFrame, which is how a stationary prop is re-validated). Include-filtering means terrain, characters and decoration are ignored by construction.

propIdToIgnore additionally drops the prop with that id from the results — needed when a prop is being moved, since its own hitbox is still parented in the container at its old position.
