Soil

dormant

The farming plot prop. A Soil is a rectangular patch that holds any number of independently planted crops, each at its own offset within the patch. It extends PropBaseClass and is also re-exported unchanged as BiggerSoil — the two differ only in item data (a larger model and a larger props.sizeModifier), not in behaviour.

Crop lifecycle

Every planted crop is a SavedCropData record inside the prop's persisted props.crops list. It carries the seed item id, the server timestamp it was planted at, a plot-relative offset (X/Y studs plus a random yaw), a random scale and a random visual modifier. From plantedAt plus the seed's floweringTime/maturityTime/harvestTime the class derives a GrowthData snapshot every frame — no growth state is stored, so growth continues while the owner is offline and needs no catch-up pass.

Life stages run Seed → Flower → Mature → Wilted, each with its own model in Assets.Crops.<CropName>. A crop marked instantlyGrown (via the developer-product instant-grow prompt) is pinned to Mature and skips the timers entirely.

Trees and produce

Seeds whose data carries cropTreeData grow into trees, which are never harvested themselves. Instead a mature tree accumulates ProduceData entries on a server timer, one per produceGrowTime, up to the number of CropAttachment points on its mature model and up to an optional lifetime produceYield. Each produce is rendered as a clone of the crop's Crop part pinned to a free attachment, scaled from MINIMUM_SCALE up to full size as it ripens, and gets its own harvest prompt on maturity. Harvesting a tree's produce leaves the tree standing; only a tree that has exhausted its produceYield is removed.

Placement rules

Planting is validated on the server: the offset must sit inside the prop's bounding box (Soil:_isOffsetWithinBounds) and at least BaseData.MIN_CROP_SPACING studs away from every existing crop (Soil:_isOffsetTooCloseToExistingCrops). Together these are exposed as Soil:CanPlantAtOffset so the client's placement preview can refuse before round-tripping.

Scale modifiers

The prop's scaleModifier multiplies the random scale given to new crops and produce. It comes from the item's props.sizeModifier, overridden by the current upgrade level's props.sizeModifier when present, and is recomputed whenever the replica's level changes — so upgrading a plot grows the things planted in it from then on.

Realms

The server owns all crop state and is the only side that mutates props.crops. The client owns models, progress bars and prompts, rebuilt from the replica in a single RenderStepped reconciliation pass (Soil:_setupCropModels) that creates, restages, rescales and destroys crop models to match server data. Harvesting is client-initiated through DispatchRemoteEvent, and only HarvestCrop and HarvestProduce are allow-listed.

Harvest input

Crops are harvested by holding BaseData.HARVEST_KEY (or the on-screen button on touch devices) and walking through them: while held, any prompt that becomes visible auto-triggers, throttled to one harvest per HARVEST_DELAY. The hold state is module-level and shared by every Soil in the world, so a single keypress sweeps a whole farm. Triggering a prompt directly still works as a single-crop fallback.

Stealing other players' crops is fully implemented behind the module-level ENABLE_STEALING constant, which is false; with it off, non-owners get no prompts at all.

Gated by FeatureFlags.BaseEnabled — disabled by default; per-project forks enable it deliberately.

Functions​

new​

</>
Soil.new(propData: PropData) → Soil

Creates a Soil prop.

Seeds the replica's props from savedPropData when the plot is being restored from a save (and with an empty crop list otherwise), then hands off to PropBaseClass.new with the four harvest signals and the HarvestCrop/HarvestProduce client allowlist.

Realm-specific setup afterwards:

  • Client — allocates crops, starts the reconciliation loop (Soil:_setupCropModels), and re-pivots every crop when the prop is moved.
  • Server — starts the tree produce timer (Soil:_startProduceTimers).

Both realms recompute Soil:_setScaleModifier on every level change.

CreateNewCropEntry​

This item only works when running on the client. Client
</>
Soil:CreateNewCropEntry(
cropData: CropTypes.SavedCropData,--

Replicated crop record

offset: CropTypes.CropOffset--

Plot-relative position and rotation

) → Crop?

Instantiates everything a newly replicated crop needs and returns the Crop bookkeeping entry for it: the stage model, an Attachment on the soil model that prompts and UI hang off (raised 2 studs so prompts float above the crop), a growth ProgressBar when the crop is neither mature nor instantly grown, and — for a mature tree — its produce mount points.

Returns nil when the seed no longer resolves, the model has not been built yet, or the offset falls outside the plot. Callers treat nil as "skip this frame".

This only builds instances; the caller inserts the result into self.crops and attaches the appropriate prompt.

AddSeed​

This item only works when running on the server. Server
</>
Soil:AddSeed(
seedItemId: string,--

Item id of the seed to plant

offset: Vector2--

Plot-relative X/Z offset in studs

) → ()

Plants a seed at a plot-relative offset.

Silently no-ops (with a warning only for an unknown seed) if the seed id is not a seed, the offset is outside the plot, or the spot is too close to an existing crop — the client is expected to have pre-checked with Soil:CanPlantAtOffset, so a rejection here means a stale preview or a tampered request.

Rolls the crop's random rotation, scale (from BaseData.CROP_SCALE_RANGE, multiplied by the plot's scaleModifier) and visual modifier at plant time, then appends it to props.crops and republishes. Consuming the seed from the player's inventory is the caller's responsibility.

CanPlantAtOffset​

This item only works when running on the server. Server
</>
Soil:CanPlantAtOffset(
offset: Vector2--

Plot-relative X/Z offset in studs

) → boolean

Whether a seed could be planted at offset right now — bounds and spacing combined. Exactly the checks Soil:AddSeed performs, exposed so a caller can test without attempting the plant.

GetCropById​

</>
Soil:GetCropById(cropId: string) → CropTypes.SavedCropData?

Looks up a planted crop's record by its cropId, reading whichever replica this realm owns. Returns nil if no crop matches — which is the normal result after the crop has been harvested.

The returned table is the live record, not a copy: mutating it and then republishing props is how Soil:InstantGrowCrop works.

InstantGrowCrop​

This item only works when running on the server. Server
</>
Soil:InstantGrowCrop(
cropId: string--

Crop to grow

) → ()

Marks a single crop instantlyGrown, pinning it to the Mature stage regardless of elapsed time. Called after the player buys the grow_crop developer product from the crop's instant-grow prompt.

Warns and no-ops if the crop id, its seed, or the seed's maturityTime cannot be resolved.

GrowAllCrops​

This item only works when running on the server. Server
</>
Soil:GrowAllCrops() → ()

Instantly matures every crop on the plot. Backs the base's "Grow All" point.

Normal crops are simply flagged instantlyGrown. Trees additionally have their produce topped up to a full set of CropAttachment slots — existing produce has its creationTime zeroed so it reads as ripe, and missing slots are filled with already-ripe produce — while still respecting the tree's lifetime produceYield.

HarvestAllCrops​

This item only works when running on the server. Server
</>
Soil:HarvestAllCrops() → ()

Harvests everything harvestable on the plot in one pass and fires HarvestedBulk with the collected items. Backs the base's "Harvest All" point.

Iterates backwards so removals do not disturb the traversal. Per crop:

  • Trees yield all their current produce and keep standing, with their produce list emptied; a tree that has exhausted its produceYield is removed from the plot at this point, since it can never bear again.
  • Normal crops yield once and are removed, but only if mature or instantly grown — immature crops are left alone.

Unlike Soil:Harvest this fires a single bulk signal rather than one Harvested per crop, so the economy layer can credit the whole haul in one transaction.

Harvest​

This item only works when running on the server. Server
</>
Soil:Harvest(
cropId: string--

Crop to harvest

) → ()

Harvests one crop: removes it from props.crops, republishes, and fires Harvested with the crop record and how long past maturity it was taken. That signal is the authoritative event the economy layer credits from.

Refuses (with a warning) if the crop id is unknown or the crop is neither mature nor instantly grown.

This is the unguarded internal path — it performs no ownership check. Client-initiated harvests go through Soil:HarvestCrop, which checks ownership and then delegates here.

HarvestCrop​

This item only works when running on the server. Server
</>
Soil:HarvestCrop(
player: Player,--

The requesting client

cropId: string?--

Crop to harvest; a missing id warns and no-ops

) → ()

Client-callable entry point for harvesting one crop — allow-listed in _allowedClientFunctions, so it is reached via DispatchRemoteEvent, never called directly.

Verifies the caller owns the plot, resolves the crop, confirms it is harvestable, then delegates to Soil:Harvest. A request for a crop that is not yet mature is dropped rather than errored — the intent is to surface a "buy instant grow?" upsell there, which is not implemented yet.

HarvestProduce​

This item only works when running on the server. Server
</>
Soil:HarvestProduce(
player: Player,--

The requesting client

produceId: string?,--

Produce to take

cropId: string?--

Tree the produce belongs to

) → ()

Client-callable entry point for harvesting a single piece of tree produce — allow-listed in _allowedClientFunctions.

Verifies ownership, locates the produce within its parent crop, removes it, republishes and fires HarvestedProduce. The tree itself is untouched and will grow the slot back on its next produce tick; the tree is only ever removed by Soil:HarvestAllCrops once its produceYield is spent.
