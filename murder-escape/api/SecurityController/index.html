SecurityController

This item only works when running on the client. Client

Client half of the anti-exploit handshake. Answers the server's liveness challenge and locally reverts the two tampering patterns that are cheap to catch from the client.

Client-side checks are advisory

Everything here runs on the exploiter's own machine and can be removed by them. Its value is the ping/pong leg: the server knows whether a client is answering, and with what. Treat the local kick and the health reset as friction, never as enforcement — authority lives in the server services.

The handshake

SecurityController.init dispatches SECURITY_INIT carrying the current secret. The server is expected to answer with its own SECURITY_INIT carrying a replacement secret, which is stored and echoed back from then on. On each SECURITY_PING the controller replies SECURITY_PONG with the character's current WalkSpeed and the stored secret, so the server can compare both against what it believes.

Local watches

  • Player.Changed on UserId or Name — impossible under normal play, so the client kicks itself with "cheater".
  • Humanoid.Changed — WalkSpeed above GlobalConstants.MAX_WALKSPEED + 1, or a NaN Health (compared as the "-1.#IND" string), zeroes the humanoid's health.

Both watches have a SECURITY_OFFENSE dispatch commented out beside them; nothing dispatches or handles that action today.

watch​

</>
SecurityController.watch() → ()

Opens every listener the controller owns, for the session — nothing here is disconnected.

  • Player.Changed for identity tampering (UserId / Name), which kicks.
  • CharacterAdded -> Humanoid.Changed for speed and NaN-health tampering, which zeroes health.
  • A red.subscribe catch-all that stores replacement secrets from SECURITY_INIT and answers SECURITY_PING with SECURITY_PONG.

Called by SecurityController.init; not meant to be called twice, since each call adds another set of connections.
