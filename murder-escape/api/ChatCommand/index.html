ChatCommand

Parses and dispatches slash commands typed into chat.

Commands are registered up front with ChatCommand.use or ChatCommand.insert, then each chat message is turned into a ChatCommand with ChatCommand.new and run with ChatCommand:process. Messages that do not start with /, or whose first word is not a registered command, are ignored.

A command's first argument is normally a target selector — me, all, others, or a partial player name — which ChatCommand.getPlayers resolves to a list of players. The selector is consumed, and everything after it is passed to the command as plain string arguments. 

ChatCommand.use({
	kill = { function(targets: { Player })
		for _, target in targets do
			target.Character.Humanoid.Health = 0
		end
	end, minimumLevel = Util.userLevel.moderator },
})

local command = ChatCommand.new({ player = player, text = message, userLevel = level })

if command then
	command:process()
end

A registered command: its handler at index 1, plus optional flags controlling how targets are resolved and who may run it.

noTargets skips selector parsing entirely, so the caller alone is the target and the first word stays an ordinary argument. adminsExempt is for punitive commands — it drops superusers from the target list so they cannot be hit by all.

Parses a chat message into a command object.

Returns nil when the text does not start with the / prefix. A parsed object whose first word is not a registered command is still returned, but with valid unset, so ChatCommand:process does nothing with it.

Errors if data.player is missing or data.text is not a string.

getPlayers​

</>
ChatCommand.getPlayers(
player: Player,--

Caller, used to resolve me and others

text: string?,--

Selector text

ignoreIfDead: boolean?--

Drop players who are not alive

) → {Player}

Resolves a target selector to a list of players.

me (or no text) is the caller, all is everyone, others is everyone but the caller, and anything else is matched as a Lua pattern against player names — returning at most one player, the first match.

Name matching is a pattern match

The selector is fed to string.match, not compared literally, so a name containing pattern characters can behave unexpectedly.

process​

</>
ChatCommand:process() → ()

Runs the parsed command, if it is valid and the speaker is permitted.

Does nothing when the message was not a recognised command, or when the speaker's userLevel is below the command's minimumLevel — an unauthorized attempt is ignored silently rather than reported.

Targets are resolved first (unless the command sets noTargets), then the handler is called as handler(targets, ...remainingWords). The handler runs on the calling thread, so a yielding command blocks the caller.
