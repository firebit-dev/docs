Analytics

Logs events to Roblox's AnalyticsService, from either realm: custom events, economy events and progression events. It also answers to the function names core's services call (logPlayerEvent, logResourceEvent, logPlayerProgression, and the no-ops below), so they need no changes.

LogCustomEvent is server-only, so this module carries a RemoteEvent: a client call forwards the payload to the server, which stamps the sending player onto it and logs it. The server trusts the client for the event name and value but never for the player, so a client cannot log events against someone else. Economy and progression events are server-only; a client call does nothing.

Event names are colon-delimited to pack extra dimensions into Roblox's three custom field slots. "Shop:Purchase:Coins" logs as event "Shop" with CustomField01 = "Purchase" and CustomField02 = "Coins". Segments past the third are dropped, and anything outside [A-Za-z0-9-_. :] becomes an underscore.

In Studio the server also prints every event it sends to Output, because Creator Hub's dashboards lag behind events by up to a day. 

Analytics.log({ event = "Shop:Purchase:Coins", player = player, value = 250 })

log​

</>
Analytics.log(
data: BaseEvent--

Event to log

) → ()

Logs an event. Safe to call from either realm.

On the client the payload is forwarded to the server and this returns immediately. On the server data.player is required — an event without one is discarded.

Invalid payloads are dropped without raising, so this never needs to be wrapped in a pcall on a hot path.
