DropsController

This item only works when running on the client. Client

Purely-cosmetic loot drops: the coin/item that arcs out of a mined node, floats on the ground, and flies into your character when you walk up to it.

Nothing here is authoritative. The server has already granted the reward before a drop is spawned; this controller animates it and fires the caller's onClaim callback at the right moment. A player who never walks over a drop still gets the reward if the caller asked for autoClaimOnDestruction.

Lifecycle

  1. Spawn — DropsController.spawnDrop clones or builds the particle part, resolves an origin (caller's origin, else the character's PrimaryPart) and a landing target, then raycasts RAYCAST_DISTANCE studs straight down from the target to find ground. Assets under ReplicatedStorage.Assets.DropsAssets are cloned onto the part; if one of them is a RewardTrail, two attachments are created for it. Plays the item-drop SFX.
  2. Flight — a 3-point Bezier (start, a control point DROP_ARC_HEIGHT studs above the midpoint scaled by distance, landing spot) drives a CFrame tween over DROP_FLIGHT_DURATION. A parallel RenderStepped connection adds tumbling spin. On completion the trail is disabled and the part snaps to the landing CFrame.
  3. Idle — unless destroyOnArrival ended it at step 2, the part starts a sine float: vertical offset of ITEM_FLOAT_DISTANCE on a FLOATING_PERIOD-second period, a half-rate horizontal wobble, and a slow continuous yaw. Runs on RenderStepped and self-disconnects if the part is deparented or gets claimed.
  4. Claim — DropsController.checkClaims runs every RenderStepped and offers every active drop to DropsController.pickupDrop. A drop is claimable once it is within DEFAULT_CLAIM_RADIUS studs of the character and at least CLAIM_DELAY seconds old — the delay is what stops a drop spawned at your feet from vanishing before you see it.
  5. Pickup — with tweenToCharacterOnClaim, the trail is re-enabled and a RenderStepped lerp pulls the part to the character's current pivot over CHARACTER_TWEEN_TIME, re-reading the pivot each frame so it tracks a moving player. Otherwise onClaim fires and the drop is removed immediately. Either path plays the item-pickup SFX.
  6. Expiry — DropsController.updateDrops runs every RenderStepped and retires anything older than its lifetime (default DROP_LIFETIME), force-claiming it first when autoClaimOnDestruction is set.

Timing constants

These are load-bearing and interact:

Constant Default What depends on it
DROP_FLIGHT_DURATION 0.3 Bezier tween length and the tumble connection's own alpha clock — they must match or the spin cuts out early
CLAIM_DELAY 0.2 Measured from dropInfo.createdAt, i.e. from spawn, not from landing. Keep it under DROP_FLIGHT_DURATION and drops become claimable mid-flight
CHARACTER_TWEEN_TIME 0.2 Pickup lerp. The particle is destroyed when it elapses, so raising it leaves the part visible longer after the SFX
DROP_LIFETIME 20 Default expiry, overridable per drop
FLOATING_PERIOD 2 Idle sine period
DEFAULT_CLAIM_RADIUS 10 Claim distance, measured against the drop's target position, not its animated position
PARTICLE_TEXT_LIFE 3 DropsController.showChange popup lifetime and its tween duration

Floating numbers

DropsController.showChange is a separate system that happens to live here. It welds one billboard to the character and accumulates gains into it: repeated calls within PARTICLE_TEXT_LIFE seconds bump the running total and reset the timer rather than spawning a second popup, and each distinct {unitType}_{itemId} gets its own label row inside the shared billboard.

Everything a caller can ask for when spawning a drop. Only particle is required.

If tweenTarget is omitted, the origin doubles as the target and targetSpread is forced on, so a drop always travels somewhere rather than landing on itself. Both spread flags apply a random offset of up to DROP_SPREAD_RADIUS studs horizontally and 0..2 vertically.

Functions​

getPlayerRootPosition​

</>
DropsController.getPlayerRootPosition() → Vector3?

Position of the local character's PrimaryPart, or nil when there is no character. Used as the default spawn origin.

spawnDrop​

</>
DropsController.spawnDrop(
data: DropData--

Drop description

) → Drop?

Spawns one drop and starts its arc. Returns the resolved Drop, or nil if no origin could be determined (no data.origin and no character).

data.particle accepts either an Instance to clone or an image asset id; a string builds an invisible part carrying a 24x24 BillboardGui with that image, so UI-style drops and 3D-model drops share one code path. 

DropsController.spawnDrop({
	particle = ReplicatedStorage.Assets.Resources.Stone:Clone(),
	origin = hitPosition + Vector3.new(0, 2, 0),
	tweenToCharacterOnClaim = true,
	autoClaimOnDestruction = true,
	onClaim = function()
		DropsController.showChange(1, "item", "Stone")
	end,
})
CAUTION

When data.onClaim is set the particle is not added to the maid directly — the maid's cleanup function fires onClaim and then destroys the part, unless a pickup lerp still owns it. That is why claimed parts are tracked separately in claimedParts.

updateDrops​

</>
DropsController.updateDrops() → ()

Expiry sweep. Driven every RenderStepped by the connection DropsController.init opens; safe to call by hand.

Retires every drop older than its lifetime, skipping any already destroying. Drops flagged autoClaimOnDestruction go through DropsController.pickupDrop with forcePickup so their onClaim still runs; the rest are dropped with DropsController.removeDrop.

removeDrop​

</>
DropsController.removeDrop(
dropId: string--

Key into the active-drops table

) → ()

Retires one drop without claiming it: marks it destroying, destroys the particle (with a CoinDespawn burst when SHOW_DESPAWN_VFX is on), destroys the maid, and clears it from activeDrops and claimedParts.

Note the maid's own cleanup still fires onClaim if the drop had one — so a caller relying on onClaim for the reward is not silently skipped when the drop is removed rather than picked up. Unknown ids are ignored.

clearAllDrops​

</>
DropsController.clearAllDrops() → ()

Destroys every active drop's maid and resets the registry and the id counter. Used by DropsController.shutdown and by anything that needs a clean slate, such as a teleport or round transition.

Unlike DropsController.removeDrop this does not destroy particles directly — it relies on each maid's cleanup, which means onClaim callbacks still fire.

showChange​

</>
DropsController.showChange(
amount: number,--

Added to the running total for this unit

unitType: "coins" | "item",--

Which family of gain

itemId: string?--

Item to resolve an icon for, when unitType is "item"

) → ()

Floating "+N" popup welded to the local character. Independent of the drop system — call it whenever a currency or item total moves.

Calls coalesce. The first call clones Assets.UI.GainVFX, welds it to the PrimaryPart and tweens its StudsOffset upward over PARTICLE_TEXT_LIFE seconds. Subsequent calls within that window add to the running total and push the expiry out instead of spawning a second billboard, so a burst of ten single-coin awards reads as one "+10".

Each distinct {unitType}_{itemId} gets its own label row cloned from the billboard's Template, so mixed gains stack: 

DropsController.showChange(1, "coins")
DropsController.showChange(1, "item", itemId)

Icons resolve from Items[itemId].icon for items and CoreImages["styled/coin"] for coins; a row with no icon falls back to showing the identifier as text and destroys its icon label. No-ops when the character has no PrimaryPart.

init​

</>
DropsController.init() → ()

Bootstrap hook. Resets the registry and opens the RenderStepped connection that drives DropsController.updateDrops.

Paired with DropsController.start, which opens the claim loop. Both are called by Bootstrap during Entry.client.luau step 4.

pickupDrop​

</>
DropsController.pickupDrop(
dropId: string,--

Key into the active-drops table

forcePickup: boolean?--

Bypass the radius, delay and arrival checks

) → ()

Claims one drop, if it is claimable. Called for every active drop each frame by DropsController.checkClaims, and directly with forcePickup = true by DropsController.updateDrops for drops flagged autoClaimOnDestruction.

Unless forcePickup is set, the drop is skipped when any of these hold:

  • it is flagged destroyOnArrival (it was already retired on landing)
  • the character is further than DEFAULT_CLAIM_RADIUS studs from targetPosition
  • less than CLAIM_DELAY seconds have passed since spawn
  • it is already claimed, or currently destroying

With tweenToCharacterOnClaim, the spawn maid is destroyed outright to stop the float, the trail is re-enabled, and a fresh RenderStepped connection lerps the part toward the character's pivot — re-read every frame — over CHARACTER_TWEEN_TIME, after which the part is destroyed and the entry cleared. Otherwise onClaim is spawned and the drop goes straight to DropsController.removeDrop. Both paths play item-pickup.

CAUTION

Errors on an unknown dropId — it indexes activeDrops without a guard.

checkClaims​

</>
DropsController.checkClaims() → ()

Claim sweep. Driven every RenderStepped by the connection DropsController.start opens.

Bails early when there is no character pivot, otherwise offers every active drop to DropsController.pickupDrop, which applies the radius and delay checks per drop.

start​

</>
DropsController.start() → ()

Bootstrap hook, run after DropsController.init. Opens the RenderStepped connection that drives DropsController.checkClaims.

shutdown​

</>
DropsController.shutdown() → ()

Tears the controller down: disconnects the claim and update loops and calls DropsController.clearAllDrops. Idempotent — both connections are nil-checked and nil'd out, so DropsController.init and DropsController.start can bring it back up.
