GameService

This item only works when running on the server. Serverdormant

Round orchestrator for the minigame rotation. Owns the lobby loop that decides when a round happens and which round it is; BaseGameMode owns what happens once one starts.

The loop

A single Heartbeat connection, installed by GameService.init, drives everything. It idles whenever a round is live, one is being set up, or the server is empty. Otherwise:

  • Not enough players — reset the intermission timer and periodically hint how many more are needed. The threshold is the lowest minimumPlayers across all registered modes, so a two-player mode can start even if others need more.
  • Enough players — accumulate toward MinigameConfig.lobbyWaitTime, then call GameService.gameWrap, which yields for the entire round.

inProgress and activeGameMode are what keep this re-entrant-safe: the Heartbeat handler keeps firing while gameWrap is yielding, and both flags stop it starting a second round underneath the first.

Picking a round

gameWrap
  └── a player paid to queue a game?  → use it
      else voteWrap
            ├── build a pool of up to `voteSlots` (mode, map) candidates
            ├── one candidate only → return it, skip the vote
            └── otherwise → VoteService, wait for the result

Once a candidate is chosen, gameWrap constructs the mode, waits out the map load, shows the round info card, and calls Start. Player count is re-checked at every one of those steps, because each yields and people leave.

DANGER

DEBUG_GAME at the top of this module is a hard override. While it is a table, the truthiness test in GameService.voteWrap returns it before any pool is built — voting never runs and the same mode and map are played every round. Leave it nil outside of debugging.

Gated by FeatureFlags.Minigames — disabled by default; per-project forks enable it deliberately. With the flag off init returns before installing the Heartbeat loop, so no round ever starts.

init​

</>
GameService.init() → ()

Bootstrap hook. Sets up the lobby loop and the client-facing game mode data.

Game mode modules are cloned into ReplicatedStorage so clients can read the configs (names, descriptions, round times) needed to render vote cards — but each clone's Init child is destroyed first, so the server-only round logic is never replicated.

It then installs the Heartbeat lobby loop described on GameService, plus a handler that catches up newly loaded players: anyone joining during an intermission receives the remaining countdown and the right music cue, and anyone joining an under-populated lobby is told how many more players are needed.

The "need N more players" hint is rate-limited to one every INSUFFICIENT_HINT_INTERVAL seconds, except that a change in N sends immediately — so the count visibly ticks down as people join rather than lagging behind.

No-ops entirely when the Minigames feature flag is off.

voteWrap​

</>
GameService.voteWrap() → MinigameTypes.VotePoolItem?--

The chosen mode and map

Runs the map/mode vote and yields until it resolves, returning the winning candidate or nil if no vote could be held.

DANGER

Returns DEBUG_GAME immediately if that constant is set — which it currently is. Everything below this line is dead until it is cleared. See GameService.

Builds a pool by filtering the registered modes down to those whose minimumPlayers the lobby can satisfy, then drawing up to MinigameConfig.voteSlots of them at random, each paired with a random map from its own map list. Returns nil if nothing qualifies, and short-circuits without a vote if exactly one candidate survives.

With a real pool it starts VoteService, broadcasts the vote countdown, and waits on either VoteEnded or a votingTime timeout — whichever comes first, with the loser cancelled. Players who load mid-vote are folded in and given the remaining time rather than a fresh timer, and are skipped entirely once fewer than two seconds remain.

Afterwards it prunes voters who left, asks VoteService for the winner, shows the result to the surviving voters, and returns the winning candidate.

gameWrap​

</>
GameService.gameWrap() → ()

Runs one complete round and yields for its entire duration. Called by the lobby loop; it sets inProgress on entry, and the caller clears it on return.

Chooses the round in priority order: a game a player paid to queue via MinigameService.getNextQueuedGame wins outright, otherwise GameService.voteWrap decides.

It then constructs the mode — which loads the map as a side effect of BaseGameMode.new — records it as activeGameMode, and clears that reference when the round destroys itself.

Before starting it waits out an estimated map load time scaled by part count (see MinigameUtil.calculateMapLoadTime), then broadcasts the round info card (mode, map, description, thumbnail, length, lives, teams) and waits four seconds for players to read it.

Player count is re-verified before every one of those waits and again after, because each yields; a lobby that drains below the mode's minimum tears the round down and returns rather than starting an unplayable game.

Finally calls BaseGameMode:Start, which yields until the round is over.
