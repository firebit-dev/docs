CurrencyService

This item only works when running on the server. Server

The authoritative money path. Every currency balance in the game is read and written through this service — nothing else should touch profile.stats.<currency> directly.

A currency type is any numeric key under stats in the profile (coins, gems, xp, points, …); the service is deliberately string-keyed rather than enumerated, so new currencies need no change here.

Write-through

All mutations funnel through one private mutate helper, which:

  1. Reads the live profile via ProfileService.get (bailing when unloaded).
  2. Runs the caller's mutator against profileData.stats inside a pcall, so a throwing mutator warns and aborts instead of half-applying.
  3. Derives the changed stats.<currency> paths from the mutator's returned table and hands them to ProfileService.update, which pushes them to the player's replica and refreshes any matching leaderstat.

Because the mutator writes into the profile's own stats table, the profile is updated in place; the ProfileService.update call is what makes the change visible to the client.

Guard rails

CurrencyService.set rejects negative amounts; CurrencyService.add and CurrencyService.take reject non-positive ones. take additionally refuses to overdraw a balance unless the caller passes override, making it the safe default for spend flows. Singular add/take floor their amount, so fractional currency can never enter the profile.

Regional pricing

CurrencyService.init registers the coins developer-product callback with MarketplaceData. Purchased coin grants are passed through adjustValueByUserPriceLevel before crediting, so the amount awarded tracks the player's regional price level rather than the flat product value.

init​

</>
CurrencyService.init() → ()

Registers the coins developer-product receipt callback with MarketplaceData.

On a successful purchase the product's value is run through adjustValueByUserPriceLevel for the buying player before being credited, so players in different regional price tiers receive an amount matched to what they actually paid. The callback's return value is the credit's success flag, which MarketplaceService uses to decide whether to grant the receipt. A credit is logged as an IAP economy Source event, item CoinPack<value> with the pack's own value.

Overwrites a balance outright. Rejects negative amounts.

Prefer CurrencyService.add / CurrencyService.take for gameplay flows — set discards whatever the balance was, so two concurrent grants can clobber each other.

Note that setting a balance to exactly 0 returns false: the success check treats the resulting 0 as absent.

Safe debit that will not allow the currency to go below 0 unless overridden.

The amount is floored and must be strictly positive. The balance is checked before the mutation: when the player cannot afford it and override is not set, nothing is written and the call returns false alongside the player's current balance so the caller can report the shortfall. Passing override skips the affordability check and permits a negative balance. 

local ok, balance = CurrencyService.take(player, "coins", price)
if not ok then
	-- `balance` is what they actually have
end

Overwrites several balances in a single replicated mutation. Every amount must be >= 0 or the whole call is rejected before anything is written.

Returns the request, not the result

Unlike CurrencyService.set, the second return value is the updates table you passed in, not the resulting balances — for a set these coincide. Note also that the math.floor in the validation loop assigns to the loop variable and is discarded, so unlike the singular variants these amounts are stored unfloored.
