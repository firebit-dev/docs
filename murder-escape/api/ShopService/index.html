ShopService

This item only works when running on the server. Server

Handles shop management, including stock for multiple shop types.

One [Replica] is created per non-custom shop defined in ShopData.SHOPS, each holding a { [itemId]: StockItem } map that is the single source of truth clients read stock from. Shops marked custom (skins, player market) ship their own component and are skipped entirely — they do not participate in the stock system.

Restock scheduling

Restocking is derived from wall-clock time rather than tracked per item. Two intervals interact:

  • ShopData.STOCK_REFRESH_INTERVAL — the global cycle. _lastRestockCycle records the cycle ordinal already processed, which is what stops a cycle from firing twice.
  • item.stockData.restockInterval — per item. An item's most recent due restock is floor(now / interval) * interval; it refills to maxStockQuantity only when that timestamp falls inside the current global window, otherwise it keeps its quantity.

ShopService.startRestockLoop polls ShopService.getTimeUntilRestock at most once a second and calls ShopService.performRestock when the window opens.

Stock is not persisted

Despite the save* naming, LocalStorage is a plain in-memory table on the server — ShopService.saveStockToLocalStorage and ShopService.saveRestockTime write no DataStore, so stock and the restock clock reset on every server start. The only DataStore this module touches is redeemed_codes, used by the redeem-code flow.

Feature gate

FeatureFlags.ScarcityShop is off by default. When off, ShopService.init never builds the shop replicas, never populates stock and never starts the restock loop, and ShopService.purchaseStock skips its stock-decrement step entirely — so stock is effectively infinite and purchases are limited only by currency and ownership limits. Handlers, redeem codes, crates and the marketplace item callback all remain active.

Computes the stock every shop should be holding right now and writes it into the shop replicas.

For each item it finds the most recent restock time that should have occurred (floor(now / restockInterval) * restockInterval) and refills to maxStockQuantity only when that moment lies inside the current global restock window; otherwise the existing quantity is carried forward. Replicas are only written when something actually changed, so an idle cycle costs no replication.

Returns whether the player can purchase the item and the number of items they own.

Items with no ownershipLimit (or a limit of 0) are unlimited and always pass. Counting differs by item type:

  • Skin — an [ItemRecord] in profile.inventory like everything else, but treated as a boolean unlock via CosmeticService.ownsSkin.
  • Prop — inventory quantity plus any props the player has already placed in the world. That second term currently always reads zero: the BaseService dependency is a local stub pending the Base system port.
  • everything else — the summed quantity of matching inventory records.

purchase​

</>
ShopService.purchase(
player: Player,--

buyer

itemId: string,--

item to buy

quantity: number?--

) → boolean

Buys a non-stocked item with soft currency.

Rejects anything hidden, unpriced, or carrying stockData — stocked items go through ShopService.purchaseStock instead. Checks the ownership limit and the balance, debits via CurrencyService.take, logs a Sink resource event, then grants one copy.

Note that quantity is asserted positive but is otherwise unused: exactly one item is charged for and granted.

purchaseStock​

</>
ShopService.purchaseStock(
player: Player,--

buyer

shopType: string,--

what shop the player is buying from

itemId: string,--

item to buy

quantity: number?--

amount, defaults to 1; priced per unit

) → boolean

Buys an item from a specific shop, honouring stock when scarcity is enabled.

The order of operations is: validate the item, check the ownership limit, verify the balance, debit the currency, then attempt the stock decrement. Because payment happens before the stock check, a failed decrement is compensated by an explicit refund (logged as a Refund resource event) rather than avoided.

The stock decrement only runs when both hold: FeatureFlags.ScarcityShop is on and the item declares stockData. With the flag off (the default) the branch is skipped entirely and stock is effectively infinite.

Skins are handled by CosmeticService.markPurchased instead of [ShopService.giveItemToPlayer]: they're recorded as a boolean unlock, not a stackable quantity, and are auto-equipped and applied to both the character and the held item.

getRestockInfo​

</>
ShopService.getRestockInfo() → table--

{ globalRefresh = {...}, shops = { [shopType] = { [itemId] = {...} } } }

Builds a debug snapshot of restock timing: the global refresh interval and the time left on it, plus per-shop, per-item restock interval, time remaining and current quantity. modulus on each entry is the elapsed time within that interval, which is what the scheduling comparisons key off.

Read-only — computing this does not advance any cycle.

manualRestock​

</>
ShopService.manualRestock(
shopType: string--

key in ShopData.SHOPS

) → boolean--

whether anything actually restocked

Force-restocks a single shop, used at boot so items are available immediately rather than after the first scheduled window.

Differs from the scheduled path in what it guarantees: items of INITIAL_STOCK_RARITY ("Common") and all props are filled to maxStockQuantity unconditionally, while rarer items only restock if their own interval boundary is within the last second — and even then they refill to 0 rather than their max, so rare stock is never seeded at boot.

Advances _lastRestockCycle on success so the scheduled loop does not immediately repeat the work, and broadcasts the restock toast.

redeemCode​

</>
ShopService.redeemCode(
player: Player,--

redeemer

payload: ShopTypes.ShopRedeemCodePayload--

carries the entered code

) → ()

Redeems a promo code from Data/ShopCodes and grants its item.

The code is upper-cased before lookup. Redemption is rejected when the code is unknown, its item does not exist, it requires Premium the player lacks, the server is Studio (codes are disabled there), or it has already been redeemed. Otherwise the redemption is written to the redeemed_codes DataStore first — the grant only happens if that write succeeds, so a datastore failure cannot produce a free duplicate.

Replies with a UI_TOAST on success or ITEM_SHOP_ERROR on any rejection.

purchaseItem​

</>
ShopService.purchaseItem(
player: Player,--

buyer

payload: ShopTypes.ShopPurchasePayload--

) → ()

Legacy catalogue purchase path, driven from the shop UI.

Checks the ownership limit (reporting owned/limit back to the player when exceeded), then debits coins by adding a negative delta through ProfileService.add rather than CurrencyService.take — so this path does not log a resource analytics event and does not share the currency service's guard rails. Items with no purchasePrice are granted free.

Crates are granted without popping the inventory open, since the client plays its own opening flow.

openCrate​

</>
ShopService.openCrate(
player: Player,--

opener

payload: ShopTypes.ShopOpenCratePayload--

) → ()

Opens an owned crate and grants a rolled item.

Verifies via ShopService.playerOwnsItem that the record really belongs to the player, rolls a reward with ShopItems.chooseCrateItem, grants it and replies with ITEM_SHOP_CRATE_OPEN. Non-common results additionally broadcast a server-wide CHAT_ALERT, delayed 6 seconds to land after the client's reel animation finishes.

Crate is not consumed

The removal of the crate record is commented out and replaced by an empty stub table, so opening a crate does not currently destroy it — the same crate can be opened repeatedly.

init​

</>
ShopService.init() → ()

Boots the service: binds the Handlers folder, and registers the item developer-product callback so a purchased item is granted through InventoryService once the receipt is processed.

The shop stock machinery — replica setup, item population, initial stock, the per-shop boot restock and the restock loop — is entirely behind FeatureFlags.ScarcityShop, which is off by default. With it off, no shop replicas exist at all and clients see no stock data.
