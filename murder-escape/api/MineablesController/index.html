MineablesController

This item only works when running on the client. Client

Client half of the mining loop: finds mineable nodes by CollectionService tag, handles hover and click, and dispatches hits to the server.

The two-model trick

Every tagged node ends up as a pair. The tagged model stays where the server put it and keeps its collision geometry for raycasts, but all of its parts are made fully transparent. A clone — the visualModel — is parented to Workspace with collision, touch and query all disabled, its tag removed (so discovery doesn't recurse), and ModelStreamingMode set to Persistent.

The point is that hit detection and visuals can then move independently: the visual model is free to squash on impact via ScaleTween without ever perturbing what the raycast sees. MineablesController.models holds these pairs bucketed by MineableType.

Attributes

Nodes are configured entirely through instance attributes; see MineableModelAttributes. Mineables.REQUIRED_MODEL_ATTRIBUTES is validated on hover, and a node missing any of them warns and is ignored. Health and MaxHealth are the server's business — the client only reads LastHitAt, HitCooldown, MineableId and OriginalScale.

OriginalScale is lazily captured on the first hit if absent, so the squash tween always has a scale to return to.

Input

Two ContextActionService bindings, both still on the legacy input path:

  • MineableDetection on mouse movement — raycasts from the camera, walks up to the tagged parent, validates it, and drops the hover if it is further than Mineables.MAX_DISTANCE. Sets the hover cursor and sinks the input while hovering.
  • MineableClick on MouseButton1 / Touch — re-resolves the target if there is no current hover (so a fast click without a preceding move still registers), then applies two independent cooldowns before dispatching.

Hit dispatch and rewards

A click that passes both cooldowns — Mineables.PLAYER_HIT_COOLDOWN against the module-local lastLocalHitAt, and the node's own HitCooldown against its LastHitAt attribute — writes LastHitAt locally for immediate feedback (the server overwrites it), dispatches MINEABLE_HIT with the node's MineableId, emits the MineableHit particle at the raycast point, and squashes the visual model to 1.3x and back.

Rewards come back asynchronously as MINEABLE_AWARD, which is subscribed in MineablesController.start and turned into a DropsController drop that flies to the character and shows a +1 popup.

init​

MineablesController.init() → ()

Bootstrap hook. Starts node discovery via MineablesController._listenForModels. Input and rewards are wired up later, in MineablesController.start.

start​

</>
MineablesController.start() → ()

Bootstrap hook, run after MineablesController.init. Subscribes to MINEABLE_AWARD and binds the two ContextActionService actions (MineableDetection, MineableClick).

The award handler looks the granted item up under ReplicatedStorage.Assets.Resources by itemId, warns and bails if there is no model for it, and otherwise spawns a DropsController drop two studs above the award position with tweenToCharacterOnClaim and autoClaimOnDestruction set — so the reward lands whether the player walks over it or not.
