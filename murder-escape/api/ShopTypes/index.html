ShopTypes

Types for shop-related operations and handlers.

Each type here is the payload for one client-to-server shop action. They are named after the action they belong to and are dispatched through the shared action layer, so the server handler for an action and the client that fires it agree on one shape.

Items are addressed two different ways depending on the verb. Buying, equipping and granting take an id — the item id from src/Shared/Data/Items/, which names a kind of item. Selling and removing take a recordId, which names one specific stack the player owns (see Types.ItemRecord). Sending one where the other is expected silently misses.

</>
interface ShopUnequipPayload {

Item id to unequip

Unequipping is by item id, like equipping: the server clears whichever slot holds it (a pet can sit in any pet slot). Only cosmetics that InventoryUtil.canUnequip allows are accepted.

interface RotationSlot {
itemId: string--

Cosmetic item id filling this slot

rarity: string--

Rarity key, see ShopData.Rarity

basePrice: number--

Undiscounted price (DIRECT_PRICES or ROTATION_FALLBACK_PRICES)

finalPrice: number--

basePrice with discount applied, floored; the price charged

discount: number--

Fraction off basePrice, e.g. 0.25 for 25% off

isWildcard: boolean?--

True for the rotation's single wildcard slot

}

One item slot in the daily rotating shop. See DailyRotationService.getRotation.
