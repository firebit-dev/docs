Device

This item only works when running on the client. Client

Author: Javi (dig1t)

Utility module for handling device-specific information and events.

Breakpoints are thresholds that trigger responsive elements to resize/reshape. They are used for adjust UI to different screen sizes and devices.

Functions​

getSize​

</>
Device.getSize() → Vector2

Usable screen size in pixels.

Measured off a private DeviceScreen ScreenGui with insets and safe-area compatibility disabled, so this is the raw viewport rather than whatever a particular ScreenGui's inset settings would report.

getWidth​

</>
Device.getWidth() → number

Usable screen width in pixels. Width is what breakpoints are keyed on.

hasTouchControls​

</>
Device.hasTouchControls() → boolean

Whether on-screen touch controls are in play — touch is enabled and this is not a console. Distinct from [Device.isMobile]: a laptop with a touchscreen answers true here and false there.

getBreakpoint​

</>
Device.getBreakpoint() → Breakpoint

The breakpoint matching the current screen width.

Walks the thresholds largest-first and returns the first one the width exceeds, so a width below every threshold lands on the smallest. Note that several breakpoint names share a pixel value (phone-small and phone are both 640, and everything from laptop-medium up is 1536), so the name returned for a shared value is whichever the flipped lookup table happens to hold — compare with Device.inBreakpoint rather than testing this for equality.

inBreakpoint​

</>
Device.inBreakpoint(
target: Breakpoint--

Upper bound to test against

) → boolean

Whether the current breakpoint is at or below target — the "max-width" test, so inBreakpoint("phone-large") is true on every phone and false on tablets and up.

This is the intended way to branch on screen size; it compares pixel thresholds rather than breakpoint names, so aliased names behave sensibly. Reads the cached lastBreakpoint rather than re-measuring.

isConsole​

</>
Device.isConsole() → boolean

Whether the client is running on a console (ten-foot interface).

forcedInputDevice​

</>
Device.forcedInputDevice() → string?

In Studio only, the input device a ForceInputDevice attribute on Workspace names ("gamepad", "keyboard" or "touch"), so a Play session can walk the gamepad paths that Studio's automation can't drive: it sends gamepad key codes as keyboard input. nil everywhere else.

isMobile​

</>
Device.isMobile() → boolean

Whether this device should get the mobile UI: any touch-capable, non-console device. See the inline comment for why this is not the stricter "touch and no keyboard/mouse" check.
