VoteService

This item only works when running on the server. Serverdormant

Runs the pre-round vote that picks the next minigame. Driven by GameService.voteWrap, which supplies the candidate pool and waits on VoteEnded.

State

One vote at a time, held in module-level state rather than on an instance:

  • pool — the VotePoolItem candidates being voted on
  • votes — game mode name to vote tally
  • voters — who is eligible to vote
  • playerEntries — who has voted, and for what

Starting a new vote while one is running stops the old one first, so the state is never mixed between rounds. VoteService.getWinner resets pool and votes as a side effect of reading them.

Ending a vote

Two ways: everyone eligible has voted (checked after every ballot), or GameService times it out. Either path goes through VoteService.stop, which fires VoteEnded exactly once and tells clients to close the UI.

Weighted votes

A player holding the double_votes gamepass casts two votes instead of one. The weight is applied symmetrically on add and subtract, so changing a weighted vote leaves the tallies consistent.

Vote changing

Whether a player may change their vote is itself flagged — see VoteService.cast.

Gated by FeatureFlags.Minigames — disabled by default; per-project forks enable it deliberately. This module has no init; it is inert unless GameService drives it, which only happens with the flag on.

Functions​

startVoting​

</>
VoteService.startVoting(payload: {
pool: {MinigameTypes.VotePoolItem}?,
voters: {Player}?
}) → ()

Opens a vote over payload.pool for payload.voters, zeroing the tallies and telling those clients to show the vote UI.

No-ops if either the pool or the voter list is missing. If a vote is somehow already running it is stopped first, so state never bleeds between rounds.

startPlayerVote​

</>
VoteService.startPlayerVote(player: Player) → boolean--

Whether they were added

Adds a player to an already-running vote and sends them the current pool. Used for players who load in mid-vote.

Returns false if they are already eligible or have already voted. Note this grows voters, which raises the bar for the "everyone has voted" early exit — deliberately, so a late joiner is not disenfranchised by the vote closing the instant they appear.

results​

</>
VoteService.results() → {[string]: number}

Returns the current tallies as { [gameModeName]: voteCount }. Broadcast to clients after every ballot so the vote cards update live.

stop​

</>
VoteService.stop() → ()

Closes the vote: clears the voting flag, fires VoteEnded, and tells all clients to dismiss the vote UI.

Guarded by the voting flag, so the redundant calls from both the timeout path and the all-voted path cannot double-fire VoteEnded.

Does not clear the pool or tallies — VoteService.getWinner does that, so the results survive long enough to be read.

cast​

</>
VoteService.cast(
player: Player,--

The voter

payload: string--

Name of the game mode being voted for

) → ()

Records a player's vote for a game mode.

:::info Gated by FeatureFlags.VoteChange When that flag is off — the default — a player who has already voted is silently ignored, making the first ballot final. With it on, the previous vote is decremented and the new one incremented, so players may switch freely until the vote closes. :::

Ignores votes when no vote is running, the payload is empty, or the player is not eligible. Players holding the double_votes gamepass move the tally by 2 rather than 1, applied to both the decrement and the increment so a changed weighted vote stays balanced.

Broadcasts the updated tallies to everyone, then closes the vote if every eligible player has now voted.

getWinner​

</>
VoteService.getWinner() → MinigameTypes.VotePoolItem

Returns the winning candidate and resets the vote state.

Seeded with a random pool entry so a round where nobody voted still produces a playable game, then replaced by whichever mode has the strictly highest tally. Strict comparison means a tie is resolved in favour of whichever mode iteration reached first — effectively arbitrary, which is acceptable for a tie.

Clears voters, pool and votes on the way out, so this may only be called once per vote.
