MarketplaceService

This item only works when running on the server. Server

Handles marketplace processing for the shop system — it owns MarketplaceService.ProcessReceipt, so every developer-product purchase in the game lands here.

Note the module table is named Marketplace locally so it does not shadow the Roblox service of the same name.

Idempotence

Roblox retries a receipt until it is granted, so the flow is built to be safe to re-enter. Three pieces of state cooperate:

  • inProgress — in-memory, keyed by PurchaseId, rejects a concurrent re-entry for a receipt already being handled.
  • profile.purchases[purchaseId] — the durable record that a receipt was granted and saved. Its presence short-circuits straight to PurchaseGranted.
  • profile.unsaved[purchaseId] — a receipt that was granted but whose profile save failed. The next retry re-attempts only the save, without re-running the grant, so the player is never given the product twice.

Both records store a timestamp rather than a boolean so they can be expired later.

Pending purchases

Some products need context that the receipt does not carry — chiefly which item a generic "buy item" product should grant. Callers stage that with MarketplaceService.setPendingPurchase before prompting, and the receipt processor passes it to the callbacks and clears it on success. Pending data is dropped when a player leaves.

Fulfilment itself lives in the callbacks registered on MarketplaceData; if any matching callback fails, or none matches, the receipt returns NotProcessedYet and Roblox retries.
