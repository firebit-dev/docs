DailyRotationService

This item only works when running on the server. Server

The daily rotating cosmetic shop: 6 slots on a 24h global UTC-day seed, so every server (and every restart) computes the exact same stock without any cached/replicated state. DailyRotationService.getRotation recomputes from scratch every call — cheap, deterministic, and immune to drift.

Feature-gated behind FeatureFlags.CosmeticShop (off by default).

purchase​

buyer

itemId: string--

item id, must be in today's rotation

) → boolean

Server-authoritative purchase of a today's-rotation item. Recomputes the rotation rather than trusting any client-cached copy, rejects items already owned, then mirrors ShopService.purchaseStock's coin flow: debit via CurrencyService.take, log a Sink resource event, refund on grant failure. Grants ownership via CosmeticService.markPurchased; skins are additionally equipped and applied, mirroring the skin branch of ShopService.purchaseStock.

selfCheck​

</>
DailyRotationService.selfCheck() → ()

Studio-only sanity check: asserts that DailyRotationService.getRotation is deterministic (same UTC day -> identical rotation) and never produces duplicate itemIds within a day. Only called from DailyRotationService.init under RunService:IsStudio().

No-op unless FeatureFlags.CosmeticShop is on. In Studio, runs DailyRotationService.selfCheck once at boot.
